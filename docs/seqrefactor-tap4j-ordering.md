# Tap4j Planner Comparison

## Scope

This is a fixed-baseline, order-only comparison on Havriil's documented
`Tap4j:462ab4c8c308` case: tap4j at commit
`fb2451c64b4d78d1db062eac6695dab2fe1af2a2`, restricted to the three classes in
`dataset/manifest_eval6.jsonl`. ORGANIC found the same 17 findings for all four
planners: 13 Feature Envy, 3 Message Chains, and 1 Long Method. No source edits,
agent calls, or OpenRouter tokens were used.

The rankings were generated by repeatedly asking each planner for its next smell
and removing that item from the unchanged baseline set. This isolates initial
ordering. It is not equivalent to a full Pi experiment, which re-detects smells
after each verified edit and can introduce or clear additional findings.

## Results

| Planner | Findings ordered | Kendall tau vs SEQ | Pair agreement vs SEQ | Mean rank displacement |
|---|---:|---:|---:|---:|
| DAPS (`greedy`) | 17/17 | 0.794 | 89.7% (122/136) | 1.65 |
| TopS (`topo`) | 17/17 | 0.750 | 87.5% (119/136) | 1.76 |
| BeFS (`bfs`) | 16/17 | 0.067 | 53.3% (64/120 shared pairs) | 4.94 |

SEQ and DAPS/TopS all select `TestTap13YamlProducer.setUp` first. BeFS takes a
different path and stops with one finding it cannot plan through its transition
model. Its pairwise statistics are computed only over the 16 findings present
in both agendas; do not treat it as a complete permutation.

## Constraint Audit

SEQ derives zero dependency edges for this particular scope, so it has zero
prerequisite violations but does not exercise a meaningful safety constraint.
TopS derives 33 preference edges, including one cyclic SCC. It has no
cross-SCC violations; six edge directions are reversed within that SCC, where
not every preference can be satisfied simultaneously. These are native-rule
audits, not a shared ground-truth dependency graph.

## Interpretation And Limits

The ranking differences are measurable, but this case does not establish that
one planner is more effective. In particular, the integrated SEQ planner uses
the shipped default severity impact fallback; on this method-level case, the
impact scores mostly tie. The SEQ code exposes a metric-provider interface, but
the normal run path does not inject CK/tree-sitter metrics. This Tap4j scope
also contains no SEQ prerequisite edges.

The harness's full agent comparison is separate: run Pi once per planner using
the same case, profile, model settings, and attempt/timeout limits. That path
uses OpenRouter and incurs model calls; the order-only command below does not.

## Reproduce The Order-Only Comparison

```bash
PYTHONHASHSEED=0 uv run python -m experiments.compare_ordering \
  --manifest dataset/manifest_eval6.jsonl \
  --case-id "Tap4j:462ab4c8c308"
```

The command checks out the pinned source into an ignored worktree, runs ORGANIC
and the Spoon indexer, then writes JSON under `data/experiments/output/`.

## Run The Full Four-Planner Agent Comparison

After completing the prerequisites in [`reproducing.md`](reproducing.md) and
setting `OPENROUTER_API_KEY` locally, run:

```bash
for planner in greedy topo bfs seqrefactor; do
  node --experimental-strip-types experiments/pi_batch.ts \
    dataset/manifest_eval6.jsonl \
    --case-id "Tap4j:462ab4c8c308" \
    --planner "$planner" \
    --concurrency 1
done
```

This full comparison can produce different smell trajectories because each
planner changes the order in which the agent attempts refactorings; keep the
